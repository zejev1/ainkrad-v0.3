# Первый автономный агент погоды

База: Ainkrad F2, `5019f6eb48dca6a62adf5e9329360e132b203208`.

Изменён только Ainkrad. Iskorka — независимый проект; его код и развитие не входят в эту работу.

Системные агенты отвечают только за функции мира. Искры — отдельная структура: агент погоды не получает их состояние и не управляет ими. Сравнение результатов изолированных тестовых запусков не является частью работающего агента и не даёт ему доступа к жителям. Код Искр в этом изменении не редактировался.

## Реализовано

- Исходная модель WeatherV21 сохранена в WeatherModelV21 с теми же формулами, сезонностью, ключами случайности и коэффициентами. Старое имя `worldWeatherV21` сохранено для всех потребителей.
- Погоду действительно рассчитывает WeatherSystemAgent. Его вход ограничен идентификатором мира, эпохой, погодной изменчивостью и мировым временем. Агент не получает жителей, мысли, память, отношения, общий WorldState, мировой RNG или хранилище.
- Агент зарегистрирован в существующем SystemAgentOrchestrator на стороне мира. Нормальная работа не требует экземпляра Cardinal.
- Поддержаны start/stop/restrict/restore/retire. Остановка или сбой управляемого исполнителя включают исходную автономную модель: климат не замирает вместе с исполнителем. Неизвестные права отклоняются.
- Контрольный метод WorldEngine проверяет ревизию и выполняется в существующей атомарной транзакции. Повтор одной команды не выполняется повторно; ошибка записи не оставляет частично изменённый мир.
- `weatherSystem` добавляется к сохранению без удаления существующих полей. Сохраняется одно текущее состояние; история погоды на каждом кадре не накапливается.
- Все прежние потребители — жители, сон, тело, лодки, карта — обращаются к агенту через совместимый интерфейс. Текущие правила их поведения сохранены.
- В интерфейсе добавлено раскрываемое поле «Системы мира» со статусом погодного агента.

## Проверки

- 42 эталонных результата получены из исходной модели принятого коммита до изменения; новый агент совпадает с ними точно.
- Проверены отсутствие дирижёра, остановка/восстановление, ограничения прав, исключение исполнителя, некорректный результат и автономный резерв.
- Проверены настоящий WorldEngine/WorldStore, сохранение, загрузка, повтор команды и добавление состояния в старое сохранение без изменения жителей и отношений.
- Целевой запуск после проверки производительности: 18/18 тестов, включая существующие проверки лодочной навигации и границ системных агентов.
- Итог общего набора тестов и сборки записывается в `WEATHER_AGENT_VALIDATION.txt` в корне пакета.

## Граница первого этапа

Это первый исполнитель и его подключение к миру. Автоматический выбор ремонта самим CardinalCore, замена реализации с миграцией, отдельный процесс Кардинала, кнопки отключения всего Кардинала и парный экран ON/OFF здесь не объявляются готовыми. Погодный агент уже не зависит от них и может быть использован на следующем этапе.

Перехватываются синхронные исключения и некорректные результаты. Прерывание бесконечного цикла требует отдельного Worker; этот вариант изоляции пока не добавлен. Остановка погодного исполнителя не означает отключение всей системы Кардинала.

Для ON/OFF-сравнения исходная модель и резерв одинаковы. Контрольный мир не ослаблен. Новая погода не расходует мировой RNG, не уменьшает возможности жителей и не меняет частоту их решений.

В архиве находятся локально проверенные исходники. Новый коммит не отправлялся в GitHub и не проходил удалённый CI. Это не публикация на Vercel.

## Проверка производительности — исправление 20 сентября

Первый выданный вариант не проходил отдельный замер производительности. В нём были строковая сериализация ключа при каждом запросе, копирование результата и одноэлементный кеш, терявший пользу при чередовании моментов времени.

Исправление сохраняет прежние формулы и точность времени. Повторные запросы получают неизменяемый общий результат. Кеш хранит максимум 16 точных моментов времени, очищается при изменении мира, эпохи, погодного закона или команды управления. Три случайных погодных коэффициента повторно используются только внутри того же двухдневного периода; сезон и температура по-прежнему рассчитываются для точного момента. Чужие реализации проверяются при получении нового результата; встроенная формула не проходит повторную проверку неизменных физических ограничений на каждом запросе. Ошибка стороннего исполнителя очищает его кеш перед переходом на резерв.

В постоянные правила AGENTS.md добавлено требование проверять стоимость каждого будущего изменения, исключать ненужные повторные вычисления и сохранять всю прежнюю жизнь мира.

Измерения: Node в локальной рабочей среде, 5 повторов с чередованием порядка версий; медианы. Это не тест Android, SPCK, браузерного FPS или большого старого мира.

| Проверка | До агента | Первый агент | Исправленный агент |
|---|---:|---:|---:|
| 200 000 запросов одного момента | 95,6 мс | 37,6 мс | 4,3 мс |
| 200 000 запросов двух чередующихся моментов | 94,5 мс | 224,9 мс | 6,2 мс |
| 200 000 последовательных минут | 96,2 мс | 231,5 мс | 51,8 мс |
| Год работы всего мира после года прогрева | 297,2 мс | 295,7 мс | 294,8 мс |
| CPU того же года | 415,4 мс | 404,6 мс | 388,8 мс |

Для всего движка подтверждено отсутствие заметного замедления в этом сценарии, а не значимое общее ускорение: разница настенного времени мала относительно разброса запусков. Ускорение запросов погоды нельзя выдавать за ускорение всего движка.

Полные снимки мира (кроме нового поля weatherSystem), все сохранённые события и память совпали точно; проверена повторная загрузка. Отдельный тест подтверждает два вычисления на миллион чередующихся запросов, неизменяемость результата, ограниченность кеша и обновление при изменении зависимостей. Данные heap включают шум сборки мусора и не доказывают отсутствие всех возможных утечек.

Сырые измерения: validation/weather-agent-performance-2026-09-20.json. Воспроизведение: подготовить git archive базового 5019f6e и первого агента 22c93de в отдельных папках; из корня исправленного проекта запустить `node --import tsx scripts/benchmark-weather.ts ПАПКА_БАЗЫ ПАПКА_ПЕРВОГО_АГЕНТА РЕЗУЛЬТАТ.json`.

Полный тестовый набор на исправленном коммите повторно не запускался. Прежние 86 прошедших файлов относятся к первому агенту; их нельзя считать полной проверкой новой версии.
